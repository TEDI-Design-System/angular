# Get started with @tedi-design-system/angular

---

### 1. Installation

```bash
npm install @tedi-design-system/angular
```

Supported Angular versions are **Angular 20, 21 and 22** — the three latest majors, following
[Angular's own release model](https://angular.dev/reference/releases). See
[Supported versions](https://github.com/TEDI-Design-System/general/wiki/Supported-versions) for the
support policy.

### 2. Add TEDI Provider (Theme + Language)

TEDI provides theming and language resolution out of the box using cookies and server/browser detection.

Add the provider to your app.config.ts:

```ts
import { provideTedi } from "@tedi-design-system/angular/tedi";

export const appConfig: ApplicationConfig = {
  providers: [...yourOtherProviders, provideTedi()],
};
```

Optional: Configure default theme or language. By default TEDI uses **"default"** theme and **"et"** language.

```ts
provideTedi({
  theme: "dark",
  language: "en",
});
```

This will:

- Resolve theme and language from cookies
- Fall back to provided defaults
- Apply correct values during SSR and browser hydration

### 3. Add styles to angular.json

```json
"styles": [
  "node_modules/@tedi-design-system/angular/index.css"
]
```

### 4. Import components from the design system

Components are published as two separate entry points:

```ts
import { ButtonComponent } from "@tedi-design-system/angular/tedi";
import { FloatingButtonComponent } from "@tedi-design-system/angular/community";
```

**TEDI-Ready** components are maintained by the TEDI team and meet the full
[Definition of Done](https://github.com/TEDI-Design-System/general/wiki/Definition-of-Done).
**Community** components are contributed and held to a lighter standard. Prefer a TEDI-Ready
component where one exists.

### 5. Use the imported components in your standalone components

Most TEDI components are attribute selectors, applied to a native element rather than used as a
tag of their own:

```ts
@Component({
  selector: "app-example",
  imports: [ButtonComponent],
  template: `<button tedi-button>Create</button>`,
})
export class ExampleComponent {}
```

# Theming

TEDI uses a theme class applied directly to the `<html>` element. Theme value is stored in **"tedi-theme"** cookie.

Available themes:

- `default`
- `dark`
- `rit`

Classes applied:

- `tedi-theme--default`
- `tedi-theme--dark`
- `tedi-theme--rit`

Theme switching with ThemeService

```ts
import { Component } from "@angular/core";
import { ThemeService, Theme } from "@tedi-design-system/angular/tedi";

@Component({
  selector: "app-theme-toggle",
  template: `
    <button (click)="setTheme('default')">Default</button>
    <button (click)="setTheme('dark')">Dark</button>
    <button (click)="setTheme('rit')">Rit</button>
  `,
})
export class ThemeToggleComponent {
  readonly themeService = inject(ThemeService);

  setTheme(theme: Theme) {
    this.themeService.theme.set(theme);
  }
}
```

This will automatically:

- Update the `<html>` theme class
- Save theme to cookie
- Persist across refreshes
- Work during SSR

---

# Language

Language resolution works just like theming. Language value is stored in **"tedi-lang"** cookie.

Available languages are defined in your translation service, e.g.:

- `et`
- `en`
- `ru`

# Example of full ApplicationConfig

```ts
import { ApplicationConfig } from "@angular/core";
import { provideTedi } from "@tedi-design-system/angular/tedi";

export const appConfig: ApplicationConfig = {
  providers: [
    provideTedi({
      theme: "dark",
      language: "en",
    }),
  ],
};
```
